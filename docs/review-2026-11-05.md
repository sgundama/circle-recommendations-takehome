# Review Report — 5 November 2026

## Scope

Two reviewers checked the submission. CodeRabbit CLI reviewed all 23 files on a temporary Git
snapshot. A manual review checked the code, the tests, the setup path, and the documents against
the assignment text. This report lists the confirmed findings, the fixes, and the remaining
risks. All 34 tests pass on Node 25.5.0 and on Node 22.23.4.

## Findings and fixes

### F1 — The declared Node version was too low. FIXED.

`package.json` declared Node 20 or newer. `better-sqlite3` 13.0.3 requires Node 22 or newer. The
quoted glob in the test script also needs Node 21 or newer. CodeRabbit confirmed this finding.
The fix sets the floor to `>=22` in `package.json`, `package-lock.json`, and `README.md`. The
test script now uses `node --test`, which works on all supported versions.

### F2 — The reference-time parser accepted invalid values. FIXED.

`Date.parse` accepted `2026-02-30` and converted it to 2 March. It also treated a timestamp
without a time zone as local time. The result depended on the host time zone.
`src/config.js` now requires a strict ISO timestamp with `Z` or a numeric offset. It checks the
calendar day, the hour, and the seconds. Invalid values fail with a clear error.
`test/http.test.js` covers five invalid inputs.

### F3 — An invalid `REFERENCE_TIME` was not rejected at startup. FIXED.

The route schema passed the raw string to the ranker. The new code validates the value in
`buildServer` and in `recommendFor`. A bad value stops the server before it answers requests.

### F4 — Unknown query parameters were silently ignored. FIXED.

`?limti=1` returned ten results instead of an error. Fastify removed the unknown key and applied
the default limit. The fix sets `removeAdditional: false`, so the schema rejects unknown keys
with `400`. A test covers a misspelt key and an extra key.

### F5 — A stored database could not be reopened. FIXED.

`openDatabase` ran `CREATE TABLE` and loaded the seed on every open. A second open failed with
"table topics already exists". The fix uses `user_version`. A new database gets the schema and
seed in one transaction. A version-1 database is reopened without changes. `test/db.test.js`
reopens a stored snapshot and compares the output.

### F6 — The reason named the wrong 30-day window. FIXED.

The text said "posts in the last 30 days". The aggregates measure the 30 days before the
snapshot date, not the 30 days before the request's reference time. With a November reference
time the API claimed activity that did not exist in that window. The text now names the window:
"15 posts in the 30 days before 2026-09-21". `test/acceptance.test.js` checks this at an
overridden reference time.

### F7 — The test suite did not detect a changed dormancy constant. FIXED.

All 26 tests passed with `DORMANT_DAYS` set to 90 instead of 180. No seed Circle sits between 21
and 235 days old, so no test exercised the boundary. `test/acceptance.test.js` now builds a
patched snapshot. It places one Circle at 100 days, one at 179, one at 180, and one at 181.
The tests fail if the constant or the comparison changes.

### F8 — The scenario tests depended on the environment. FIXED.

The scenario and reason tests used the ambient `REFERENCE_TIME`. With the variable set to 2027,
14 of 26 tests failed. Each suite now passes an explicit reference time. A new test runs the
scenario files in a child process with a different `REFERENCE_TIME` and requires zero failures.

### F9 — Database connections stayed open in tests. FIXED.

Tests opened databases and never closed them. Each suite now closes its database in `after` or
`t.after`.

### F10 — The design document exceeded one page. FIXED.

`DESIGN.md` rendered to two A4 pages at 11 pt. It now has 417 words and fits the one-page intent.
The "How I worked with AI" note moved into the production section to save space.
